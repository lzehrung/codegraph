# LLM PR Review Enhancements Plan

## Step 1 – Persist index metadata for incremental rebuilds

- Update `src/indexer.ts` to write/read a manifest under `.codegraph-cache/index-v1/manifest.json` storing the last indexed commit, graph options, and per-file signatures reused across runs.
- Extend cache entries to keep resolved specifiers so unchanged files don’t need to re-run `collectGraph`.
- Document the new manifest format and cache behavior in `README.md`.

## Step 2 – Integrate git diff–based change detection

- Add helper(s) in `src/util.ts` (or a new `src/util/git.ts`) to run `git diff --name-only` / `git ls-tree` safely from Node, with fallbacks when git isn’t available.
- Expose new CLI flags (`--changed-since <ref>`, `--git-base <ref> --git-head <ref>`) in `src/cli.ts` so `codegraph index` and `graph` can auto-select files via git instead of scanning everything.
- Pipe the resulting file list into `buildProjectIndexFromFiles` to avoid touching unrelated files during PR reviews.

## Step 3 – Create an incremental index/graph API

- Implement a `buildProjectIndexIncremental` entry point in `src/indexer.ts` that loads the manifest, calls git helpers to find changed files, reindexes only those, and merges results back into the cached graph.
- Ensure `src/graphs.ts` can accept a pre-existing `Graph` object and update only the affected nodes/edges when provided with the changed file set.
- Add unit tests under `tests/cache-invalidation.test.ts` (or new suites) to cover: unchanged runs are skipped, changed files are reprocessed, and manifest mismatches trigger a full rebuild.

## Step 4 – Ship a PR-review friendly output bundle

- Introduce a new CLI surface (e.g., `codegraph review --base <ref> --head <ref>`) that orchestrates: incremental index build, dependency graph delta, impacted symbols/files, and candidate tests.
- Produce a structured JSON report (file graph diff, symbol-level impact, suggested reviewers/tests) optimized for LLM consumption; reuse existing logic in `src/impact/*.ts` where possible.
- Add documentation/examples under `docs/` plus integration tests in `tests/impact-*.test.ts` showing an end-to-end PR review run with incremental indexing.

## Step 5 – Expand language parity for PR reviews

- Re-enable Vue/Svelte graph support by uncommenting the adapters in `src/languages.ts` and `src/bootstrap/treeSitterLanguages.ts`, ensuring their definitions include `graph` queries comparable to JS frameworks.
- Add missing sample files and tests under `tests/languages/` to validate imports/exports + chunking for these SFC languages, so frontend-heavy PRs get the same coverage.
- Update `README.md` “Supported languages” and “Extending to other languages” sections to reflect the expanded coverage and new PR-review tooling.
